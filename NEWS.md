- Fixed `faststructure_backend()`'s ancestry replicates carrying no fit metric at all: fastStructure writes its converged marginal likelihood to its own `<output-prefix>.<K>.log` file, not to the `structure.py` process's stdout/stderr that `run_faststructure()` was already capturing (which is effectively empty). `run_faststructure()` now parses that native log for `Marginal Likelihood = X` and records it per K; `faststructure_backend()` passes it through as the replicate's `marginal_likelihood` metric. This was silently breaking `select_ancestry_k()` -- the documented cross-backend K-selection consensus mechanism -- for any real run mixing fastStructure with ADMIXTURE/sNMF, since fastStructure had zero available metrics and `select_ancestry_k()` errors closed rather than silently skipping a backend. Found and fixed while starting the canonical `ancestry_three_backend` evidence-record contract for release issue #24; confirmed the fix against real chr22 replicate data.
- Fixed `run_admixture_cv()` silently running non-independent "replicates": it set an `ADMIXTURE_SEED` environment variable that the ADMIXTURE binary does not read (confirmed empirically -- `strings` on the installed 1.3.0 binary shows it documents a `--seed=X` command-line flag, not an environment variable; repeated runs and runs with different `ADMIXTURE_SEED` values produced byte-identical Q matrices and log-likelihoods). `admixture_command_arguments()` now takes an explicit `seed` parameter and passes `--seed=X` on the command line, matching how `--cv=` is already passed; different seeds now produce genuinely different Q matrices and CV errors, as multi-replicate stability evidence requires. Found while proving out a real-data three-backend ancestry validation run for release issue #24: ADMIXTURE reported perfect (`stability = 1.0`) replicate agreement at every K from 2 to 10, which turned out to be an artifact of five identical runs rather than genuine convergence robustness.
