# Autosomal quantitative baseline proposal

Phase 0.9.32 adds a bounded quantitative execution after successful structural validation of the approved 1000 Genomes Phase 3 chromosome 22 source. The execution creates a scientific-review proposal; it does not approve a production baseline or authorize a release.

## Fixed analysis contract

The proposal runner derives biallelic SNPs from `22:20000000-21000000` into a temporary work directory. It then runs the package pipeline with the approved panel, sample and variant missingness thresholds of 0.20, MAF 0.05, LD pruning at r2 0.20, seed 42, ten requested principal components, and four compute threads. Only PCA is selected for this bounded execution.

Six observations are retained:

- derived interval variant count;
- retained sample count;
- QC-passing variant count;
- LD-pruned variant count;
- PC1 variance proportion;
- PC2 variance proportion.

The four counts use exact proposal comparators. The variance proportions use a relative tolerance of `1e-6` to allow supported numerical-library variation. These settings and values remain proposals until scientific review explicitly accepts or revises them.

The manual **Canonical real-data production validation** workflow runs this step only when `dataset: chr22` and `confirm_production: true`. Structural validation must pass first. The source VCF, derived VCF, tabix indexes, and transient GDS remain in runner temporary storage.

#### PCA variance-proportion caveat (resolved 2026-07-30)

`pca_pc1_variance_proportion` and `pca_pc2_variance_proportion` are computed as `eig$values / sum(eig$values)` in `R/ordination.R` (`run_pca()`), where `eig$values` comes from `normalize_pca_eigenvalues()` after it discards SNPRelate's trailing `NaN` eigenvalue slots (see `R/pca_eigenvalue_suffix.R` and `tests/testthat/test-pca-trailing-eigenvalues.R`). Because `SNPRelate::snpgdsPCA()` is called with `eigen.cnt = requested_components` (10 here), only the top 10 eigenvalues are ever computed; the denominator is the sum of *those 10 values only*, not the total genetic variance across the full eigenspectrum (rank-bounded by the 350 LD-pruned SNPs). This was verified empirically: the 10 proportions in `13_PCA_variance.tsv` sum to exactly `1.000000000000000`.

Consequently, "PC1 variance proportion = 0.2655" means PC1 accounts for 26.55% of variance *among the ten requested/computed components*, not 26.55% of total genetic variance in the dataset. This is consistent, tested, deliberate behavior applied package-wide, not a defect specific to this proposal.

**2026-07-30 — Marc-Olivier Duceppe:** decided to **keep the existing definition as-is**. The package-wide "proportion relative to the requested/computed components" convention is accepted; no code or metric-definition change is required. **Approved**: `pca_pc1_variance_proportion = 0.26553988138366075` and `pca_pc2_variance_proportion = 0.17740063253018323` stand as proposed, with relative tolerance `1e-6` accepted as appropriate for numerical-library variation across BLAS/eigensolver implementations for a deterministic, seed-fixed computation. Any caption, manuscript text, or downstream use of these two metrics should still state the qualified definition explicitly ("proportion of variance among the ten computed principal components") rather than an unqualified "percent of variance explained," to avoid readers over-interpreting the number as total genetic variance.

All six registered metrics (`subset_variant_count`, `retained_sample_count`, `qc_variant_count`, `ld_pruned_variant_count`, `pca_pc1_variance_proportion`, `pca_pc2_variance_proportion`) are now reviewed and approved. This note record is a step toward, but does not itself constitute, formal promotion: promotion still requires `approve_canonical_real_data_baseline_snapshot()` and a formal, signed review packet (see `inst/scripts/scientific_review_packet.R`), which independently covers sample inventory, source/derived checksums, environment provenance, and reviewer conflict-of-interest confirmation beyond the six quantitative metrics reviewed here.
